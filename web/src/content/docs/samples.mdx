## How to explore a sample

1. **Read its README.** Each sample starts with the shape of the application and the shortest path to running it.
2. **Run the happy path.** Start the sample as instructed, perform its documented action, and check its expected result before changing code.
3. **Open Chronicle Workbench when Chronicle is involved.** Compare the resulting events and read-side state with the action you just performed.
4. **Change one thing.** Add a fact, a view, or a user interaction and see which parts of the slice move together.

## Focused examples and full applications

A focused sample intentionally leaves things out so one concept stays easy to see. The larger applications show how those concepts meet in a real repository. Neither is a production template. Follow the selected sample's README for its prerequisites and local-development assumptions. If the sample does not build at your installed package version, report the failure in the Samples repository instead of treating the documentation site's build as a sample check.
