Cratis Studio is a collaborative workspace for developers, domain experts, and product owners to design an application's behavior before implementing it. Teams edit [Cratis Screenplay](/screenplay/) event models together: commands describe what people want to do, events record what happened, and read models describe the views people need. Studio is a paid product built on Cratis Chronicle and an optional part of Cratis Platform.

## Design before you build

Before implementing a feature, agree on what happens, who asks for it, and
what they need to see afterwards. An event model puts those decisions in a
shared picture. For an order, that means distinguishing the request to place
it from the fact that it was placed and the view that shows its status.

Studio keeps that conversation in a shared canvas with live editing, presence,
and cursors. Organize commands, events, and read models into slices, then keep
their specifications and screen designs beside them. The model remains a
Screenplay model rather than a separate diagram to translate later.

<Aside type="tip" title="Use the model in Play">
Press Play to send a modeled command and inspect the resulting state in an
application powered by [Stage](/stage/). The isolated session runs supported
model behavior and executable specifications, with a rendered frontend, backend
OpenAPI reference, read-model browser, and Chronicle Workbench. Its event store
is in memory: this is a disposable sandbox, not a production deployment or a
production operations console. To run a Screenplay locally, follow the
[Stage Docker walkthrough](/stage/docker/) and bind published ports to `127.0.0.1`.
</Aside>

## Generate implementation code

When you are ready to implement a slice or feature, inspect its planned code
before starting a generation job. Then follow the job's progress and results.
This path produces code you can review and develop, separately from the sandbox
session. Local Git operation does not require a GitHub connection.

To use AI features, your organization must configure a reachable model provider
and an agent. Studio supplies no AI model of its own, and AI features stay off
until that setup is complete. The Static + AI mode adds implementation to models
that already render statically; it cannot fill required implementation gaps.
Review and test the generated output, then complete the integrations and
deployment your application needs.

## Where it fits

Studio is built on [Chronicle](/chronicle/) and adds a shared modeling workspace
to Cratis Platform. Adopting Studio is not required to build with Chronicle,
[Arc](/arc/), or [Components](/components/). You can also use Studio to model an
event-driven system without adopting those tools for your application.

For application code, continue with [Build a full-stack feature](/build-a-full-app/)
to see how a command, event, read model, query, and React screen connect. To
inspect and operate a deployed Chronicle system, use the [CLI](/cli/) and the
Chronicle Workbench.
