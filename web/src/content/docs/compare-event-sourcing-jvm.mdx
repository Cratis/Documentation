For Java or Kotlin, first decide whether you want a framework to organize commands, queries, and handlers, or an event server behind an application model you choose. Axon Framework supplies application infrastructure. KurrentDB and Cratis Chronicle are separate servers used through client SDKs.

The Cratis team wrote this guide; Chronicle is our product. This selection guide replaces the historical capability matrix without treating frameworks and database clients as equivalent bundles.

## Comparison layers

A handler that updates a view needs someone to invoke it, checkpoint progress, and retry failures. That responsibility can sit in a framework, a subscription consumer, or a server-managed observer. It is separate from where the events are stored.

## What is being compared

Axon Framework and Axon Server are distinct products. Likewise, a KurrentDB or Chronicle client has its own release cycle, independent of its server. Compare the framework, server, and SDK versions separately.

## Core comparison

Axon Framework's [Spring integration](https://docs.axoniq.io/axon-framework-reference/5.4/spring-boot-integration/) discovers handlers and configures command, query, and event infrastructure. KurrentDB's [Java SDK](https://github.com/kurrent-io/KurrentDB-Client-Java/blob/v1.2.1/README.md) provides database access; choose your application wiring around it. Chronicle's [Spring starter](https://github.com/Cratis/Chronicle.Kotlin/blob/v7.13.0/Documentation/guides/spring-boot.md) registers processing artifacts with the kernel. Its request integration is for Spring Boot 4 with servlet MVC, not WebFlux.

## Where each option fits

### Axon Framework and Axon Server

Choose Axon Framework when you want its command, query, and [event-processor model](https://docs.axoniq.io/axon-framework-reference/5.4/events/event-processors/) to structure a JVM application. Its [storage infrastructure](https://docs.axoniq.io/axon-framework-reference/5.4/events/infrastructure/) includes Axon Server, PostgreSQL, aggregate-based JPA, and in-memory options. Aggregate-based storage is not interchangeable with a global event stream. Review the selected engine's contract and Axon Server's own edition and license terms separately from the framework.

### KurrentDB

Choose KurrentDB when you want its stream database and [persistent subscriptions](https://docs.kurrent.io/server/v26.2/features/persistent-subscriptions.html) while retaining your application model. Persistent subscriptions checkpoint on the server and deliver at least once; they do not guarantee ordering. Your consumer must tolerate duplicates. See [KurrentDB vs Chronicle](/compare/kurrentdb-vs-chronicle/) for processing and hosting details.

### Cratis Chronicle

Choose Chronicle when you want the kernel to coordinate event processing and read-model production. The [architecture](https://github.com/Cratis/Chronicle/blob/v19.181.2/Documentation/architecture.mdx) separates kernel projections from reducer and reactor handlers in your application. The JVM starter supplies artifact discovery and activation; it does not remove the kernel deployment or make application side effects atomic with an append.

## Questions to answer before choosing

- Should a framework own command and query dispatch, or will you choose that layer separately?
- Which process owns checkpoints and retries?
- Does the Spring integration match your servlet or reactive application?
- Which SDK operations and server versions does your feature require?

## Decision criteria to verify separately

Evaluate a conflicting append, a failed handler, replay, and a consumer restart on the intended storage engine. Check authentication, tenant isolation, backup, restore, and license terms for the actual deployment. This guide does not compare Axon Server editions.

## Limitations

This is an architectural selection guide, not a benchmark, reliability assessment, or client-parity claim. A framework covering more application concerns is a fit decision, not a higher score.
