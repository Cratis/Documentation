## What EventModelers.ai is

The event model puts screens, commands, events, and read models on a shared timeline. A slice selects one behavior from that flow. [Event Modeling](/event-modeling/) explains the notation and the four patterns: State Change, State View, Automation, and Translation.

Before handing a slice to an agent, record the decisions that make it implementable:

1. **Describe the behavior.** Name the command, the facts it should record, and the read model a screen needs.
2. **Keep the reasoning.** Include rules, examples, and the reason for a choice in the slice's description, notes, and specifications. Resolve open questions before marking the work `Planned`.
3. **Review the implementation.** Compare the resulting fields, events, and executable specifications with the slice definition. If the model changes, check what implementation work remains; a board status does not prove that the code has caught up.

<Aside type="note" title="Not a Cratis product">
EventModelers.ai is built by [Nebulit](https://github.com/Nebulit-GmbH), independent of Cratis. Cratis maintains the **Build Kits** linked below. See [eventmodelers.ai](https://eventmodelers.ai) for the platform itself, including workshops, pricing, and the modeling UI.
</Aside>

## What a Build Kit does

The C# kit installs a starter application, an agent loop, prompts, and build skills. The loop handles pending board tasks and separately checks local slice indexes for work marked `Planned`. It passes the corresponding prompt to the coding agent; the agent's instructions select a skill for a command/event pair, a projection/read model, or a reactor.

Those instructions ask the agent to implement the slice, build it, run the slice's tests, commit, merge to `main`, and update its status. They describe the requested workflow, not a guarantee that it succeeds. Review the changes and check results before accepting the feature. A generated application or a `Done` status is not evidence that the intended behavior works.

Each kit's *The Loop and Triggers* page owns its input layout, configuration, and trigger details: [C#](/eventmodelers-ai/csharp/understand/the-loop/), [Kotlin](/eventmodelers-ai/kotlin/understand/the-loop/), and [Java](/eventmodelers-ai/java/understand/the-loop/). Follow the chosen kit's guide rather than assuming the C# workflow or supported features apply to another language.

## Before you start the C# kit

For the **C# kit**, you need Node.js 18 or later, Claude Code (or its documented Ollama runner), and an EventModelers.ai account with a board for board-connected work. For Kotlin or Java, follow the language-specific guide linked above; prerequisites and installer behavior may differ.

<Aside type="caution" title="Review the installer and agent permissions">
The C# installer writes starter files into the current directory, can overwrite files with the same names, and installs dependencies. The Claude runner bypasses agent permission checks, and its prompts request commits and merges to `main`. Review those effects and what the agent may access before starting it. Use an isolated workspace, not an existing valuable project; a new directory alone does not restrict the agent's permissions.

Your API token can be saved in `.eventmodelers/config.json` in the project root as well as inside `.build-kit/`. The installer adds `.build-kit/` to `.gitignore`, but not the root configuration. Add `.eventmodelers/` to `.gitignore` yourself before you commit, and review configuration storage before supplying credentials.
</Aside>

The C# setup starts with these steps; follow the [C# kit guide](/eventmodelers-ai/csharp/) for the full procedure:

1. **Install** in a new, empty directory: `npx github:Cratis/Eventmodelers-Build-Kit-CSharp install`. It copies a Cratis starter app into the project root and the agent loop into `.build-kit/`.
2. **Connect a board** by giving the kit your EventModelers.ai organization, board, and API token (from [app.eventmodelers.ai/account](https://app.eventmodelers.ai/account)).
3. **Run the loop** with `node .build-kit/ralph-claude.js`, then mark a reviewed slice `Planned` on your board. Inspect the resulting changes and build and test results before accepting the work.
