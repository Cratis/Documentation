If you want a coding agent to work from a described behavior, the **Cratis Build Kits** connect that work to an Arc + Chronicle application. Use this page to decide whether the optional integration fits, choose a language, and understand what you must review before trusting the output.

You can write Cratis applications without Studio, an EventModelers.ai board, event modeling, or a coding agent. These kits choose Arc + Chronicle together; that choice does not make Chronicle a requirement for Arc. If you prefer to implement the behavior yourself, start with [Build a full-stack feature](/build-a-full-app/).

## What EventModelers.ai is

[EventModelers.ai](https://eventmodelers.ai) provides a visual timeline of screens, commands, events, and read models. A slice describes a behavior to implement; its model gives the developer or agent context beyond a task title. [Event Modeling](/event-modeling/) explains the notation.

A model still needs review. Check that the slice describes the intended behavior before asking an agent to implement it, then compare the resulting code with that description. A board status does not establish that the code is correct or that later model changes have reached the application.

<Aside type="note" title="Not a Cratis product">
EventModelers.ai is built by [Nebulit](https://github.com/Nebulit-GmbH), independent of Cratis. Cratis maintains the Build Kits that integrate with it. Workshops, pricing, and the modeling UI belong to EventModelers.ai, not the Cratis Platform.
</Aside>

## What a Build Kit does

The kit supplies the connection between work definitions and an agent running in your workspace. In the C# path, the responsibilities are:

- **The kit** installs a starter application, the local loop, prompts, and skills. The loop finds work and passes prompts to the coding agent.
- **The agent** edits the application. Its prompts ask it to implement the slice, build, test, commit, merge, and update status. Those instructions are not guarantees that every step succeeds.
- **Arc** supplies the application's command and query handling; **Chronicle** supplies event persistence. The kit does not replace those runtime products.
- **You** review the model, generated changes, build and test results, and the behavior of the application before accepting the work.

The C# loop has two independent sources of work. With board configuration, it handles pending board tasks. Separately, it scans local slice indexes for work marked `Planned`; that check also runs when there are no pending board tasks. Without platform credentials, it can scan local definitions without board synchronization, but it still needs suitable local inputs and the coding agent. This is not a credential-free setup walkthrough.

Read the language-specific loop explanation for input layout, configuration, and trigger details: [C# loop and triggers](/eventmodelers-ai/csharp/understand/the-loop/), [Kotlin loop and triggers](/eventmodelers-ai/kotlin/understand/the-loop/), or [Java loop and triggers](/eventmodelers-ai/java/understand/the-loop/). Do not assume the C# mechanics apply unchanged to another kit.

## Pick your language

Before setup, read the chosen kit's requirements and installation effects. For the C# path, the installer uses Node.js, the starter targets .NET 10, and the Claude runner requires Claude Code. Board-connected work also needs an organization, a board, an API token, and the service base URL; the [EventModelers.ai account page](https://app.eventmodelers.ai/account) is the starting point for account credentials.

<Aside type="caution" title="Review the C# installer and agent permissions first">
Setup writes starter files into the current directory, can replace files with the same names, and installs dependencies. The C# Claude runner bypasses agent permission checks. It can execute commands and modify the project; its prompts also request commits and merges to `main`.

Inspect the kit in an isolated, disposable workspace without credentials, not an existing valuable checkout. Do not start the agent until you have reviewed those effects and decided what it may access. A separate directory alone does not restrict the agent's permissions.

The installer can save credentials in `.eventmodelers/config.json` at the project root as well as inside `.build-kit/`. Ignoring `.build-kit/` does not protect the root configuration. Keep credentials out of version control and review configuration storage before connecting a board.
</Aside>

Choose the kit for your application's language, then follow its own guide rather than combining setup steps:

- [C# Build Kit](/eventmodelers-ai/csharp/) — the .NET path for Arc + Chronicle applications.
- [Kotlin Build Kit](/eventmodelers-ai/kotlin/) — the Kotlin path using Arc.Kotlin + Chronicle.Kotlin.
- [Java Build Kit](/eventmodelers-ai/java/) — the Java path using Arc.Kotlin + Chronicle.Kotlin.

After an agent works on a slice, inspect the file changes and Git history, confirm the build and relevant tests, and exercise the intended behavior. Generated code, tests, and a `Done` status are outputs to review, not proof that the slice meets its requirements. If configuration is unclear, unexpected files change, or checks fail, stop the loop and resolve the problem before allowing more work.
