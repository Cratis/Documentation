The [Cratis Discord community](https://discord.gg/kt4AMpV8WV) is the place to ask questions about evaluating, building with, or operating Cratis Platform components. You do not need to be a customer or contributor. Community help is best-effort, with no guaranteed response time; use GitHub issues for reproducible bugs and proposals that need a lasting record.

For documentation questions, [Cratis Prompter](/prompter/) answers from the published docs with citations. It responds automatically in the help forum and dedicated ask channel. Elsewhere on the server, mention it or use `/ask`. Follow its source links to check the answer.

<Aside type="caution" title="What you post to Prompter leaves Discord">
Prompter sends your question to Anthropic to generate an answer and Voyage AI to find relevant documentation. It can also include recent messages from the same public channel or thread as context for Anthropic. Prompter does not keep a stored copy of question or answer text. Your posts and any maintainer hand-off messages remain in Discord. Do not paste secrets, credentials, customer data, or logs containing personal data. See [Prompter privacy](/prompter/concepts/privacy/).
</Aside>

## Where to ask

| When you need... | Start with... |
|---|---|
| A cited answer to a documentation question | [Prompter on Discord](/prompter/) |
| Help deciding whether Cratis fits your system | [Cratis Discord](https://discord.gg/kt4AMpV8WV) |
| A second pair of eyes on an event model, projection, command, or slice | [Cratis Discord](https://discord.gg/kt4AMpV8WV) |
| Help with a tutorial, sample, local setup, or first application | [Cratis Discord](https://discord.gg/kt4AMpV8WV) |
| A reproducible bug in a product | The matching [GitHub issue tracker](#github-issue-trackers) |
| A feature request or design proposal | GitHub issues, with Discord for early discussion |
| Suggestions, rough edges, or documentation gaps | [Feedback and suggestions](/feedback/) |
| Private, dedicated, or commercial help | [Work with us](/work-with-us/) |
| To understand how dedicated help differs from community help | [Professional help](/professional-help/) |
| A suspected vulnerability | [Security](/security/), never a public issue |
| Contribution workflow, coding standards, or build setup | [Contributing](/contributing/) |

If you are not sure which product owns the problem, ask in Discord first. If Prompter cannot answer, ask a person in the same thread. Where the **Ask a human** button is available, the person who asked can use it to notify the configured maintainer role. This requests help; it does not promise a response time.

## How to get a useful answer

You can ask early. When you have the details, include the parts that make the problem reproducible:

- What you are trying to build or decide.
- Which Cratis component or combination of components you are using.
- The package or Docker image versions, if you know them.
- The command, event, projection, query, component, or configuration involved.
- The expected behavior and what happened instead.
- Error messages, trimmed logs, screenshots, or a small repository when the problem depends on runtime behavior.

Remove connection strings, tokens, certificates, and personal or customer data from anything you post. Discord threads and GitHub issues are public.

<Aside type="tip" title="Design questions are welcome">
If the question is more about modeling than a specific exception, describe the business decision you need to make and the facts you already have. That is often enough for a useful event-sourcing conversation.
</Aside>

## Community expectations

We want Cratis to be useful to people who are learning, evaluating, operating, and contributing. Be clear about what you need, assume good intent, and keep discussions respectful. The [Code of Conduct](/contributing/code_of_conduct/) applies to the community spaces and the repositories.

Start with the [Cratis Discord community](https://discord.gg/kt4AMpV8WV), then move durable bugs, proposals, and documentation changes into the relevant GitHub repository when the thread becomes actionable.
