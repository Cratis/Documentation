Cratis Chronicle's Python package does not yet provide a client API for connecting, authenticating, or appending events. The source package, `cratis_chronicle`, exposes only `__version__`, so installing it does not let a Python application store events in Chronicle. If you need an application client now, compare the [.NET, TypeScript, Kotlin/Java, and Elixir clients](/chronicle-clients/) and their language-specific capabilities.

<Aside type="note" title="No Python package published">
The [Python client repository](https://github.com/Cratis/Chronicle.Python) documents that `cratis-chronicle` is not published to PyPI. A source checkout can be installed for contribution with Python 3.10 or later, but it has no usable client API. Its generated-contract dependency comes from a pinned Chronicle release wheel, not PyPI. Follow the repository's contributor setup if you want to work on the client, or ask in [the community](/community/) about your application's needs.
</Aside>

Building your own integration is a different task from installing a client. Chronicle exposes gRPC contracts, but generated messages alone do not handle authentication, event registration, or the connection lifecycle. [Building a client](/chronicle/building-a-client/) explains that work. For an AI agent that needs to inspect or operate a running Chronicle, the [Chronicle MCP server](/chronicle-mcp/) provides a separate connection; it is not a Python application SDK.
