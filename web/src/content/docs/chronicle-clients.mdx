## Event sourcing for .NET

The .NET SDK provides typed access to event stores and logs, with APIs for read models, projections, reducers and reactors. It also covers constraints, migrations, namespaces and hosting integration, including a [.NET Aspire resource](/chronicle/hosting/aspire/). Start with the core package:

```bash
dotnet add package Cratis.Chronicle
```

In an ASP.NET Core application, add `Cratis.Chronicle.AspNetCore` instead; it brings in the core SDK and the `AddCratisChronicle` / `UseCratisChronicle` hosting integration.

- [Event sourcing in .NET](/event-sourcing/dotnet/) — the dedicated landing page
- [.NET client docs](/chronicle/clients/dotnet/) · [Get started](/chronicle/get-started/)
- [`Cratis.Chronicle` on NuGet](https://www.nuget.org/packages/Cratis.Chronicle)
- [Chronicle on GitHub](https://github.com/Cratis/Chronicle)

## Event sourcing for TypeScript and Node.js

Use `@cratis/chronicle` from a TypeScript or Node.js application. It builds on the `@cratis/chronicle.contracts` gRPC contracts package and includes APIs for transactions, jobs, webhooks, OpenTelemetry and compliance features for personally identifiable information (PII). Install the client and its dependencies:

```bash
npm install @cratis/chronicle @cratis/fundamentals reflect-metadata
```

The client supports standard decorators (TypeScript 5.2 or later) and legacy decorators. Enable `experimentalDecorators` and `emitDecoratorMetadata` only for the legacy option; leave them unset for standard decorators. Use an ES module project. The [TypeScript landing page](/event-sourcing/typescript/) lists the setup.

- [Event sourcing in TypeScript and Node.js](/event-sourcing/typescript/) — the dedicated landing page
- [TypeScript client docs](/chronicle/clients/typescript/)
- [`@cratis/chronicle` on npm](https://www.npmjs.com/package/@cratis/chronicle)

## Event sourcing for Kotlin and Java

Kotlin and Java applications use the same JVM client, `io.cratis:chronicle`. Choose the core library or the Spring Boot starter for hosting integration; a testing library is also available.

```kotlin
// build.gradle.kts
dependencies {
    implementation("io.cratis:chronicle:<version>")
    // Or, in a Spring Boot application:
    implementation("io.cratis:chronicle-spring-boot-starter:<version>")
}
```

Replace `<version>` with the current release from Maven Central.

- [Event sourcing in Kotlin and Java](/event-sourcing/kotlin/) — the dedicated landing page
- [Kotlin/Java client docs](/chronicle/clients/kotlin/)
- [`io.cratis:chronicle` on Maven Central](https://central.sonatype.com/artifact/io.cratis/chronicle)
- [Chronicle.Kotlin on GitHub](https://github.com/Cratis/Chronicle.Kotlin)

## Event sourcing for Elixir

Add `cratis_chronicle` to your Mix dependencies for an Elixir application. The client supports transactions, optimistic concurrency checks, webhooks and reconnection.

```elixir
# mix.exs
defp deps do
  [
    {:cratis_chronicle, "~> <version>"}
  ]
end
```

Use the current version from Hex; `mix hex.info cratis_chronicle` prints it.

## Event sourcing for Go

`github.com/cratis/chronicle.go` is the Go client for Chronicle. It supports typed event registration, connection with TLS and OAuth, single and atomic batch appends, and event history reads. Observers, projections, and automatic lifecycle recovery are not yet implemented.

```sh
go get github.com/cratis/chronicle.go@v0.11.0
```

[v0.11.0](https://github.com/Cratis/Chronicle.Go/releases/tag/v0.11.0) is the latest released tag checked on 2026-10-20.

- [Event sourcing in Go](/event-sourcing/go/) — the dedicated landing page
- [Go client docs](/chronicle/go/)
- [Chronicle.Go on GitHub](https://github.com/Cratis/Chronicle.Go)

## Any language, one contract

The [client SDK docs](/chronicle/clients/) describe the language-specific APIs over Chronicle's shared gRPC contracts. A shared protocol does not mean every client exposes every feature; Go, for example, supports appending and reading events but not observers or projections. If your runtime is not listed above, you can implement the contracts directly.

Before installing a client, check [Compatibility](/compatibility/) to pair it with a Chronicle kernel, the server runtime. Clients other than .NET have independent release schedules, and their major versions do not match the kernel's. Then follow your language's setup guide above to connect an application.
