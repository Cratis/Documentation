<TopicHero icon="laptop" eyebrow="Tools" title="Explore Chronicle from your editor">
When you're deep in a slice and something looks wrong, the question is usually "what's actually *in* the event log?" **Narrator** answers it without a context switch: it adds a Chronicle Explorer to the VS Code activity bar, so you can browse your event store, page through a sequence, and inspect event and read-model schemas right next to the code you're writing.
</TopicHero>

## Install it

Narrator is published on the Visual Studio Marketplace as **[Cratis Narrator - Chronicle Explorer](https://marketplace.visualstudio.com/items?itemName=cratis.narrator)** (publisher `cratis`).

<Steps>

1. Open the **Extensions** view in VS Code (`⇧⌘X` / `Ctrl+Shift+X`).

2. Search for **Narrator** and install **Cratis Narrator - Chronicle Explorer**, or install it from the [Marketplace listing](https://marketplace.visualstudio.com/items?itemName=cratis.narrator).

3. Open the **Narrator** icon in the activity bar. It connects to your active Chronicle context on startup. If no context is configured, run **Narrator: Connect to Chronicle** from the Command Palette and enter a server URL.

</Steps>

The source lives at [github.com/Cratis/Narrator](https://github.com/Cratis/Narrator).

## How it connects

Narrator reads the **same configuration file the [CLI](/cli/getting-started/) uses**, `~/.cratis/config.json`, so if you've already pointed the CLI at a store, the extension picks it up. A minimal config looks like this:

```json
{
  "activeContext": "default",
  "contexts": {
    "default": {
      "server": "chronicle://localhost:35000"
    }
  }
}
```

A context can also name an `eventStore` and a `namespace`. It connects to the active context on startup and watches the file, reloading when it changes. To use a config in a non-standard location, set the `narrator.configPath` setting; leave it empty to use `~/.cratis/config.json`.

<Aside type="caution" title="The config file can hold secrets">
A context can carry client credentials (`clientId` and `clientSecret`) and an access token, stored in plain text. Keep `~/.cratis/config.json` out of source control and out of shared folders, and use per-developer credentials you can rotate.
</Aside>

## What you can do

<CardGrid>
  <Card title="Browse the store" icon="seti:db">
    Navigate event stores and namespaces down to their event types, read models, observers, and projections in the Chronicle Explorer tree.
  </Card>
  <Card title="Page through events" icon="list-format">
    Open an event sequence into a paged viewer showing sequence number, event type, event source, when it occurred, and the payload.
  </Card>
  <Card title="Inspect schemas" icon="seti:json">
    Open an event type's or read model's JSON schema, and open a projection's declaration.
  </Card>
  <Card title="Switch contexts" icon="right-arrow">
    Add, edit, delete, and switch between Chronicle server contexts without editing JSON by hand.
  </Card>
</CardGrid>

A **Details** pane sits below the explorer and shows the selected node's context and content as key/value tables, so selecting an event or read model shows its data inline.

<Aside type="note" title="Read only">
Narrator only reads: the log, observers, and schemas. It has no commands that replay observers, manage jobs, or change application state. For operational actions, use the [CLI](/cli/) or the Workbench; the [Chronicle MCP server](/chronicle-mcp/) can also stop, resume, and delete jobs. Application state still changes only through commands and events.
</Aside>
