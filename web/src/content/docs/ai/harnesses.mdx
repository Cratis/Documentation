Cratis AI supports two independent installation paths:

- **Managed repository setup** — `cratis ai install` resolves the repository's
  selected profiles and languages, installs the shared corpus in `.cratis/ai`,
  and configures every selected harness.
- **Native plugin setup** — install one harness's plugin or package for convenient
  access without the Cratis CLI. You do not get the shared corpus, multi-harness
  configuration, or hash-protected update and uninstall lifecycle.

Use the managed path when a team wants consistent guidance across tools. Use a
native plugin when one developer wants Cratis guidance in one harness.

## Managed harness support

```bash
cratis ai install \
  --harnesses claude,codex,copilot,cursor,opencode,pi \
  --profiles cratis/application \
  --languages csharp,typescript
```

The available values come from the AI repository's
`.cratis/ai/manifest.json`. The CLI creates only the native adapters selected by
the repository:

| Harness | Managed project integration |
| --- | --- |
| Claude Code | `.claude` rules, agents, commands, skills, and hook settings |
| OpenAI Codex | `AGENTS.md` and `.agents/skills` |
| GitHub Copilot | `.github` instructions, agents, prompts, and skills |
| Cursor | `.cursor` rules, agents, commands, and skills |
| OpenCode | `AGENTS.md` plus `.opencode` agents, commands, and skills |
| Pi | `AGENTS.md` plus `.pi` agents, prompts, skills, and Cratis extensions |

All adapters point back to `.cratis/ai`; they do not create divergent copies of
the corpus. Run `cratis ai status` to inspect local modifications and
`cratis ai uninstall` to remove only integrations the CLI created.

## Claude Code plugin

```text
/plugin marketplace add Cratis/AI
/plugin install cratis@cratis
```

Remove it with `/plugin uninstall cratis@cratis`.

## OpenAI Codex plugin

```bash
codex plugin marketplace add Cratis/AI
codex plugin install cratis@cratis
```

## GitHub Copilot plugin

```bash
copilot plugin marketplace add Cratis/AI
copilot plugin install cratis@cratis
```

## Cursor plugin

Add `Cratis/AI` in Cursor's plugin settings. Cursor reads the committed
`.cursor-plugin/marketplace.json` and installs the canonical Cratis skills.

## Pi package

```bash
# Project-scoped
pi install -l npm:@cratis/pi

# User-wide
pi install npm:@cratis/pi
```

The package reads `.cratis/ai.json` when present and exposes the selected skills.
Without that file, it exposes every packaged skill. It also contributes packaged
rules and prompts through Pi's extension API. It does not create `.cratis/ai`,
configure other harnesses, or provide managed hash protection.

## OpenCode without the CLI

OpenCode consumes standard project resources directly. Add your own content to
`.opencode/agents`, `.opencode/commands`, and `.opencode/skills`, and use
`AGENTS.md` for repository instructions. There is no separate Cratis OpenCode
plugin required for this path.

<Aside type="note" title="Your harness folders remain yours">
The managed installer refuses to overwrite an existing user-owned adapter. You
can also add files beside Cratis-created links in any harness folder. Force only
replaces or removes files and links already recorded as Cratis-managed.
</Aside>
