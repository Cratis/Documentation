Choose Cratis AI profiles by what the repository is for: building an
application, contributing to a framework, or writing documentation. That
choice determines which rules and task skills the CLI installs. Then name
the languages you use so language-scoped guidance can be selected.

## Choose the profile

| Repository | Profile |
| --- | --- |
| .NET application on Arc and Chronicle, with a React frontend | `cratis/application/csharp` |
| .NET application on Arc without Chronicle | `cratis/application/arc-only` |
| Application on the Kotlin clients | `cratis/application/kotlin` |
| Application on the TypeScript Chronicle client | `cratis/application/typescript` |
| A Cratis framework repository (library, kernel, client SDK) | `cratis/engineering/<language>`, for example `cratis/engineering/csharp` |
| Any repository with documentation | add `cratis/documentation` |

`cratis/application` includes the application language profiles. Prefer the
language-specific profile unless the repository needs several of them.

Application profiles teach the agent to work in vertical slices: the code
and tests for one behavior. They also bring application rules for model-bound
commands and read models, and for the frontend's Model-View-ViewModel (MVVM)
structure. Engineering profiles bring framework-contributor rules instead.
Product profiles such as `cratis/arc` or `cratis/chronicle` select product
skills but provide neither rule set on their own. A documentation profile can
sit alongside either family.

The source repository's `.cratis/ai/manifest.json` lists the profiles, languages,
and harnesses `cratis ai install` accepts. An unknown value fails validation
with the rejected value. Run `cratis ai profiles list` to see the public and
engineering profiles, or use `cratis ai profiles list --source <path>` to read
a local checkout without a download. The [CLI reference](/cli/ai/) covers the
selection options.

A profile identifier describes guidance, not product feature parity across
languages. Public profiles in this catalog are also distinct from the
selected skills in the separate `Cratis/AI.Distribution` bundle.

## Configure the repository

<Steps>

1. Run the installer from the repository root. With interactive input it
   prompts for each choice:

   ```bash
   cratis ai install
   ```

2. For a non-interactive run, pass the selection explicitly. Harnesses and
   profiles are required when input is redirected; include languages too:

   ```bash
   cratis ai install \
     --harnesses claude,cursor,opencode,pi \
     --profiles cratis/application/typescript \
     --languages typescript
   ```

3. Review `.cratis/ai.json` and the installed files before committing them.
   The example above records this selection:

   ```json
   {
     "schemaVersion": "1.0",
     "harnesses": ["claude", "cursor", "opencode", "pi"],
     "profiles": ["cratis/application/typescript"],
     "languages": ["typescript"]
   }
   ```

</Steps>

The CLI follows the profiles included by your selection and uses the language
list to filter those child profiles. A profile you name explicitly stays
selected even if its declared languages do not match. Matching skills are
installed; agents, prompts, and hooks are included independently of the
profile selection. Rules are filtered by both profile and language.

<Aside type="caution" title="Always list your languages">
`--languages` narrows the skills a profile composes, and omitting it leaves the
skills unconstrained. Rules behave differently: a rule scoped to C# or
TypeScript files is installed only when that language is listed. Name every
language the repository uses.
</Aside>

<Aside type="note" title="Configuration is not ownership">
`.cratis/ai.json` records your selection, not a source revision pin.
`.cratis/ai.manifest.json` records the source revision, managed file hashes,
and owned integrations. Putting your own file in a managed or harness folder
does not make it Cratis-owned.
</Aside>

## Update or change a selection

To change products, languages, or harnesses, run `install` again with the new
options. To pick up newer guidance for the selection you already have, run:

```bash
cratis ai update
```

The update adds selected content, removes Cratis-owned content no longer
selected, and updates the harness links. Add `--dry-run` first to review that
plan. An edited managed file blocks the update before writes; preserve any
project-specific guidance in your own files before deciding whether to use
`cratis ai update --force`. That flag permits replacing edited managed corpus
files, but does not override conflicts with your files or changed Model
Context Protocol (MCP) server entries.
[Getting started](/ai/getting-started/) covers ownership and source selection.

## Use a native plugin instead

For one person using one coding tool, a native plugin avoids a
repository-managed copy of the guidance and its ownership manifest. The Claude Code, Codex, GitHub Copilot,
and Cursor plugins from `Cratis/AI` expose the skills without reading your
profile selection. The separate public distribution contains a selected
subset. The Pi npm package can use profiles:

```bash
pi install -l npm:@cratis/pi
```

`@cratis/pi` reads `.cratis/ai.json` when it exists and exposes the skills for
those profiles and languages; without it, the package exposes all skills.
Neither native route creates the shared `.cratis/ai` corpus, configures other
harnesses, or provides CLI ownership checks. Use the [agent harness guide](/ai/harnesses/)
for installation commands and the [distribution guide](/ai/trust-and-distribution/)
for versioning and rollback.
