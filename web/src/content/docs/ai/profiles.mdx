Profiles select the product guidance a repository needs. Languages narrow a
composed profile so, for example, a TypeScript Chronicle client does not receive
C#-only skills.

## Choose the profile

| Repository | Profile |
| --- | --- |
| Arc + Chronicle application | `cratis/application` |
| Arc without Chronicle | `cratis/arc` |
| Chronicle client or service | `cratis/chronicle` |

The AI repository's `.cratis/ai/manifest.json` is authoritative for the profiles,
languages, and harnesses currently offered by `cratis ai install`.

## Configure the repository

<Steps>

1. Run the interactive installer:

   ```bash
   cratis ai install
   ```

2. Or provide every selection for automation:

   ```bash
   cratis ai install \
     --harnesses claude,cursor,opencode,pi \
     --profiles cratis/chronicle \
     --languages typescript
   ```

3. Review and commit `.cratis/ai.json`:

   ```json
   {
     "schemaVersion": "1.0",
     "harnesses": ["claude", "cursor", "opencode", "pi"],
     "profiles": ["cratis/chronicle"],
     "languages": ["typescript"]
   }
   ```

</Steps>

The CLI resolves composed profiles using the selected languages, installs the
matching skills, installs shared rules and supporting assets, and creates the
selected harness adapters.

<Aside type="note" title="Configuration is not ownership">
`.cratis/ai.json` records what your repository wants. `.cratis/ai.manifest.json`
records exactly which installed files and integrations Cratis owns, including
their hashes. User-created files are never claimed merely because they live in a
managed or harness directory.
</Aside>

## Update or change a selection

Edit `.cratis/ai.json` when the repository's products, languages, or harnesses
change, then run:

```bash
cratis ai update
```

The update adds newly selected content, removes obsolete Cratis-owned content,
and reconfigures harness links. It stops before making changes if a managed file
or integration was modified locally. Review the conflict before using
`cratis ai update --force`.

## Use a native plugin instead

A native plugin is independent of the managed path. It is useful when one person
uses one harness and wants to keep content in that harness's familiar folders.
For Pi:

```bash
pi install -l npm:@cratis/pi
```

The Pi package reads `.cratis/ai.json` when it exists and exposes the selected
skills; without it, the package exposes all skills. Native plugins do not create
the shared `.cratis/ai` corpus, configure other harnesses, or provide the CLI's
hash-protected lifecycle.
