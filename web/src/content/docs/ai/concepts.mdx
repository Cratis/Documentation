---
title: Cratis AI concepts
description: Understand the corpus, configuration, profiles, managed ownership, harness adapters, and native plugins.
---

| Concept | Meaning |
| --- | --- |
| **Corpus** | The reusable rules, agents, prompts, skills, hooks, and harness assets under `.cratis/ai`. |
| **Configuration** | `.cratis/ai.json`, the repository-owned selection of harnesses, profiles, and languages. |
| **Profile** | A product-oriented selection such as `cratis/application`, `cratis/arc`, or `cratis/chronicle`. |
| **Skill** | An Agent Skills package containing `SKILL.md` and optional references, scripts, and assets. |
| **Rule** | Persistent repository guidance that the selected harness loads through its native adapter. |
| **Managed manifest** | `.cratis/ai.manifest.json`, which records every Cratis-owned installed file, harness integration, and hash. |
| **Harness adapter** | A native `.claude`, `.cursor`, `.opencode`, `.pi`, `.github`, or `.agents` path that points to the shared corpus. |
| **Native plugin** | A single-harness installation independent of the managed CLI lifecycle. |

The repository owns its configuration and every file it adds. The installer owns
only paths listed in the managed manifest. An unknown path is never claimed or
overwritten, even with `--force`.

Profiles and languages decide which skills are installed. Shared rules, agents,
prompts, and supporting assets remain available through each selected harness's
native integration.

Use [Start using Cratis AI](/ai/getting-started/) for the managed workflow and
the [agent harness guide](/ai/harnesses/) to compare native plugins.
