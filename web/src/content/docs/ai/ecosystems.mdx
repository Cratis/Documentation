Cratis authors one corpus and exposes it through native harness adapters. The
adapter changes discovery, not the rule or skill body.

## Managed support

`cratis ai install` supports these harness values:

| Harness | Project resources |
| --- | --- |
| Claude Code | `.claude` |
| OpenAI Codex | `AGENTS.md`, `.agents/skills` |
| GitHub Copilot | `.github` |
| Cursor | `.cursor` |
| OpenCode | `AGENTS.md`, `.opencode` |
| Pi | `AGENTS.md`, `.pi` |

The CLI resolves profiles and languages once, installs the result in
`.cratis/ai`, and points every selected harness there. This is the recommended
multi-harness path.

## Native distribution

Claude Code, Codex, GitHub Copilot, and Cursor can install the `cratis` plugin
from the `Cratis/AI` marketplace manifests. Pi can install `@cratis/pi` from npm.
OpenCode can consume standard project folders directly.

Native installation is intentionally independent of the CLI. It is convenient
for one harness, but it does not create a shared corpus or provide managed,
hash-protected updates and uninstall.

## Quality

The repository verifies corpus structure, profile composition, skill scenarios,
harness adapters, and the Pi package from `Source/Verification`. It does not use
provenance ledgers, generated inventories, or evidence chains as substitutes for
behavior checks.
