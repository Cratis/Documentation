---
title: "Scenario: Cratis maintainer"
description: Configure a Cratis repository with shared framework guidance and its native agent harness folders.
---

You contribute to a Cratis framework or product repository rather than building
an application on it.

## Configure the repository

Use the managed installer and select the products, languages, and harnesses that
the repository actually uses:

```bash
cratis ai install \
  --harnesses claude,codex,copilot,cursor,opencode,pi \
  --profiles cratis/arc \
  --languages csharp,typescript
```

Start the agent from the repository root so it reads `AGENTS.md`, the selected
Cratis corpus, and product-local guidance.

## Keep repository guidance local

Put product-specific or confidential guidance in the owning repository. You can
add rules and skills under `.cratis/ai` or directly in one harness's native
folder. The managed manifest records only files installed by Cratis, so these
additions survive update and uninstall.

Generalize reusable guidance before proposing it to `Cratis/AI`; do not move
private product facts into the shared corpus.

## Use a native plugin for one harness

A maintainer who uses one harness can install the `cratis` marketplace plugin or
`@cratis/pi` instead. That path provides packaged guidance but not the shared
multi-harness corpus or managed lifecycle.

See [Using AI as a Cratis maintainer](/ai/cratis-maintainers/) for the complete
workflow.
