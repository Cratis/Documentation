Use a Cratis AI native plugin when you work alone and want Cratis guidance in
one coding tool without maintaining a shared guidance tree in your repository.
For Claude Code, the plugin makes Cratis skills available without a managed
install.

## What you do

Install the plugin for your harness, the tool that runs your coding agent. The
[agent harness guide](/ai/harnesses/) lists the native plugin options and their
commands. For Claude Code:

```text
/plugin marketplace add Cratis/AI
/plugin install cratis@cratis
```

That is the whole setup. There is no `.cratis/` directory to create and no
configuration file to commit.

## What you get

The skills give your assistant Markdown instructions and references for tasks
such as writing a command, modeling an event flow, or adding a projection. The
marketplace plugin adds no hooks, scripts, Model Context Protocol (MCP) server,
or files in your project.

The plugin carries skills only. It does not install the always-on Cratis rules,
the slash-command prompts such as `new-vertical-slice`, or the subagents. If you
want those, run `cratis ai install` in the repository (see
[Start using Cratis AI](/ai/getting-started/)). For Pi, `@cratis/pi` includes
rules, prompts, agents, and quality hooks as well as skills; it is not a
skills-only plugin.

Your own configuration stays yours. Keep whatever you already have in
`.claude/` (or your harness's equivalent). The plugin does not touch it.

## Keeping current

The marketplace install above follows the default branch of `Cratis/AI`; it
does not pin a guidance revision. Update the plugin through your harness, or
uninstall it to remove its guidance. For Pi, `@cratis/pi` has numbered npm
releases that you can pin. Follow
[updates and rollback](/ai/scenarios/updates-and-rollback/) when you need to
control which revision your assistant receives.

## Things to avoid

Do not copy the `Cratis/AI` repository's `.cratis/ai`, `.claude`, `.github`, or
skill folders into your own repository by hand. The copy goes stale without
warning. Use a plugin, or the managed install, which records what it installed
and can update it.
