A shared repository can support several people and several agent harnesses from
one committed source: `.cratis/ai`.

## What you do

Run `cratis ai install` in the repository root, select the required harnesses,
profiles, and languages, then review and commit the generated configuration and
corpus.

| Path | What it carries |
| --- | --- |
| `.cratis/ai.json` | The selected harnesses, profiles, and languages. |
| `.cratis/ai/` | Cratis-managed rules and skills plus user-owned additions. |
| `.cratis/ai.manifest.json` | Managed source identities and installed hashes. |
| Harness adapters | Symlinks or settings references pointing to `.cratis/ai`. |

A configuration can select more than one harness and profile:

```json
{
  "harnesses": ["claude", "codex", "pi"],
  "profiles": ["cratis/chronicle", "cratis/arc"],
  "languages": ["csharp", "typescript"]
}
```

## What you get

- **One source.** Harness integrations point to `.cratis/ai`; they do not copy
  divergent skill directories.
- **Safe lifecycle.** The local manifest hashes every managed file. Update and
  uninstall stop before changing anything if one was modified locally.
- **User extensions.** Add local rules and skills under `.cratis/ai`; they are
  never claimed, deleted, or overwritten by Cratis.

<Aside type="note" title="Resolving a modified managed file">
Run `cratis ai status` to see the paths whose hashes changed. Restore the intended
file or use `cratis ai update --force` / `cratis ai uninstall --force` only when
you deliberately want to replace or remove that modified managed content.
</Aside>
