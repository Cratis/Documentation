---
title: Configure Cratis AI for multiple coding tools
description: Configure multiple AI coding tools from one managed Cratis AI corpus, with shared profile and language selections and reviewable repository updates.
---

Use the Cratis AI managed install when a repository needs guidance for several
coding tools, such as Claude Code, Cursor, and Codex. One installed corpus, the
shared set of guidance files, supplies the selected harnesses without separate
copies for each tool.

## Configure the repository

Install the [Cratis CLI](/cli/getting-started/) first. From the repository root,
select the harnesses (coding tools) that need adapters and the profiles
(guidance sets) that fit your work. This example configures all six harnesses
for a C# application with TypeScript:

```bash
cratis ai install \
  --harnesses claude,codex,copilot,cursor,opencode,pi \
  --profiles cratis/application/csharp \
  --languages csharp,typescript
```

Keep the harnesses your team uses. Profiles and languages select the guidance;
harnesses select how the tools receive it. The
[agent harness guide](/ai/harnesses/) explains what each integration loads.

Run `cratis ai status` to check the installed selection and any locally changed
managed files. Commit `.cratis/ai.json`, `.cratis/ai.manifest.json`, the managed
`.cratis/ai` content, and the harness adapters together.

## What you get

Profiles and languages are resolved once for the selected harnesses. Each tool
still reads its native integration, such as `.claude`, `.cursor`, `.opencode`,
or `.pi`, connected to `.cratis/ai`. The files share a source; how an agent uses
them still depends on its harness and the task.

Updates preserve user-owned content and stop before overwriting a locally
edited managed file. Run `cratis ai status` and `cratis ai update --dry-run`
before applying an update. These commands download the source corpus by
default, even for status and dry runs. For offline use or a fixed revision,
point them at a local checkout with `--source <path>`. Follow
[updates and rollback](/ai/scenarios/updates-and-rollback/) to review a change
or return to an earlier installation.

When you no longer need the integration, inspect `cratis ai uninstall --dry-run`
before running `cratis ai uninstall`.

## Native plugins remain optional

For guidance in just one tool without a managed install, a developer can use a
marketplace plugin or `@cratis/pi`. Marketplace plugins carry skills only; the
Pi package also contributes rules, prompts, agents, and quality hooks. Neither
configures other harnesses or provides the CLI's ownership checks. The Pi
package yields to an existing managed installation to avoid duplicate resources.
