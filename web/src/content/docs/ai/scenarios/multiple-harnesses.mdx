---
title: "Scenario: multiple harnesses"
description: Configure several AI tools from one managed Cratis AI corpus and one repository-owned selection.
---

Use the managed path when several harnesses work in the same repository.

## Configure the repository

```bash
cratis ai install \
  --harnesses claude,codex,copilot,cursor,opencode,pi \
  --profiles cratis/application \
  --languages csharp,typescript
```

Commit `.cratis/ai.json`, `.cratis/ai.manifest.json`, the managed `.cratis/ai`
content, and the harness adapters your team wants to share.

## What you get

- **One corpus.** Every adapter points to `.cratis/ai`; no harness receives a
  separately maintained copy.
- **One selection.** Profiles and languages are resolved once for all selected
  harnesses.
- **Native folders.** Team members still use `.claude`, `.cursor`, `.opencode`,
  `.pi`, and the other folders they expect.
- **Safe updates.** `cratis ai update` stops before overwriting a locally changed
  managed file or integration. User-owned files remain untouched.

Run `cratis ai status` before an update and `cratis ai uninstall` when removing
the managed integration.

## Native plugins remain optional

A developer can still install a native marketplace plugin or `@cratis/pi`
without the CLI. That single-harness path does not create the shared corpus,
configure the other harnesses, or provide hash-protected lifecycle management.
