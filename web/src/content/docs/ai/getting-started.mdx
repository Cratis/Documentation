**Cratis AI is a plugin for your AI coding tool.** It bundles roughly fifty
skills — step-by-step, verified guidance for building event-sourced and CQRS
applications on the Cratis ecosystem. Install it and you're done: the skills
are passive markdown that your assistant loads when a task matches one. No
hooks, no tools, no MCP server, no executable code.

## Install it

One command block per host. The marketplace source is the `Cratis/AI`
repository's default branch, so what you install is exactly what a reviewer
reads there ([Cratis/AI#264](https://github.com/Cratis/AI/issues/264)):

```text
Claude Code:    /plugin marketplace add Cratis/AI
                /plugin install cratis@cratis

Codex:          codex plugin marketplace add Cratis/AI
                codex plugin install cratis@cratis

GitHub Copilot: copilot plugin marketplace add Cratis/AI
                copilot plugin install cratis@cratis

Cursor:         resolves the same skills through its committed
                marketplace manifest — no extra install step.

Pi (npm):       pi install -l npm:@cratis/pi
```

The same marketplace also carries a separate maintainer plugin,
`cratis-engineering`, for people contributing to Cratis' own repositories.

The [agent harness guide](/ai/harnesses/) walks **every harness type** —
Claude Code, Codex, GitHub Copilot, Cursor, Pi and npm, plus the pending
hosts (Kiro, Junie, Gemini CLI) — with exact install, verify, and uninstall
steps for each.

## What you get

- **Passive skills only.** Each skill is a `SKILL.md` (plus references and
  assets). Your assistant auto-loads the matching skill from the task
  description, or you can invoke one explicitly by name.
- **Verified guidance.** Skills are authored against pinned product versions
  in one canonical repository and reviewed there.
- **No lock-in.** Skills never write into your project, never mutate your
  settings, and removing the plugin removes everything they added.

That's all you need. The rest of this page is for when you come back later
and want more than the whole bundle.

## Narrow the scope (optional)

The plugin carries everything. A repository that wants a narrower scope — one
product, one language, one architecture — records that in a committed
`.cratis/ai.json` naming a profile under the `cratis/` namespace:
`cratis/chronicle/kotlin`, `cratis/arc/csharp`, `cratis/application`, and so
on. See [Profiles](/ai/profiles/) for the full map and what each composition
implies.

## The operating tools (separate from the skills)

The skills teach your assistant the Cratis *way*. Separately, Cratis ships
documented **operating tools** an assistant can run against a live system:

<Steps>

1. **Install the Cratis CLI** — see the
   [CLI getting-started guide](/cli/getting-started/), then run `cratis init`
   in your project so the assistant discovers documented Chronicle inspection
   and diagnosis commands instead of inventing shell syntax.
2. **Refresh after a CLI upgrade** with `cratis init --refresh`.
3. **Connect Chronicle MCP** when your host supports MCP — see the
   [Chronicle MCP setup guide](/chronicle-mcp/) — and review every requested
   capability before enabling mutating operational tools.

</Steps>

<Aside type="note" title="Status">

- **Install today from `main`.** The versioned-release flow — exact-version
  Pi packages, reviewed update pull requests — is designed but not published
  yet. The marketplace installs follow the default branch, and the published
  `@cratis/pi` npm package is a supported stable release
  carrying the whole public skill set.
- **Vendor marketplace listing is pending.** Adding `Cratis/AI` as a
  marketplace works now; being *listed* in a vendor's own marketplace UI — so
  strangers can find "cratis" by search — is a separate manual submission
  per host, tracked in
  [Cratis/AI#147](https://github.com/Cratis/AI/issues/147).
- Marketplace installs follow the `Cratis/AI` default branch; the npm package
  is a supported stable release until the governed per-profile release gates
  pass.
